# 鹈鹕骑行 · Pelican on a Bicycle

![鹈鹕骑行 · 宣传图](promo/capsule-1232x704.jpg)

一只鹈鹕骑着一辆通勤自行车环游海岛 —— 纯 WebGL / three.js 实时 3D 场景，
现在也是一个小游戏：捕鱼、计时赛、特技连击、拍照任务。

**模型、动画与音频仍然全部由代码生成**：地形、海面、天空、云、鸟群、自行车、
鹈鹕（含 3000 片羽毛）、灯塔、鸟巢、跳台、海鸥、萤火虫、所有音效与界面图标，都在运行时构建。
从 v2 美术更新起，表面细节改用一小组**由 gpt-image-2.5 生成的贴图**（沙 / 湿沙 / 草甸 / 岩石、
海面细浪与白沫、木纹、灯塔墙面、羽毛、粒子精灵）以及界面插画（模式卡、拍照任务徽章、加载页主视觉），
共约 5.5 MB —— 详见下文「美术资源」。贴图只是增强：任何一张加载失败都会自动回退到原来的程序化外观。

在线试玩：<https://cpulxb.github.io/pelican-bike-3d/>

## 玩法

开场是主菜单，背景就是实时运行的海岛。

| 模式 | 说明 |
|---|---|
| **观光模式** | 原来的样子：自动环岛骑行 + 遥测面板，可切手动。按 `Esc` 打开菜单。 |
| **捕鱼 · 喉囊** | 3 分钟。近岸浅水里会出现发光的涟漪，鱼一条条跃出水面 —— 骑过去 / 跳起来用喙接住。鱼进了喉囊，喉囊会肉眼可见地鼓起来，车也变「重」（上坡更慢、下坡更快）。送到三个鸟巢或灯塔得分：一趟送得越多倍率越高，灯塔额外 ×1.5。涉水时判定范围更大，但涉水会减速。 |
| **检查点计时赛** | 环岛 10 个悬浮光环 × 3 圈。飞行圈计时，分段与最佳圈实时对比（−绿 / +红）。最佳圈存进 localStorage，并以半透明「幽灵车」回放陪你跑。`R` 回到上一个检查点。 |
| **特技连击** | 2 分 30 秒。冲上跳台腾空，空中 `A`/`D` 转体、`W`/`S` 压头 / 抬头、`B` 摇铃加分。落地时车头要对准飞行方向、俯仰和侧倾都要在容差内，否则摔车并清空连击。连击槽在 5.5 秒内续上就继续累乘（最高 ×5）。 |
| **自由探索** | 不计时，以上所有系统全开。 |

**随时可做的拍照任务**（游戏里按 `P`）：日落灯塔、头顶的鸟群、跃出水面的鱼、嗷嗷待哺的雏鸟、腾空瞬间、萤火之夜、海鸥来袭、守夜人、与幽灵同框。
判定用这一帧相机的视锥 + 地形遮挡采样 + 天色（`sky.time` / 夜色），完成的照片缩成 320×180 存进**相册**（localStorage，最多 24 张，可下载 / 删除）。

**世界事件**
- 喉囊满了（或装了三条以上时随机）**海鸥**会飞来盘旋、轮流俯冲叼鱼 —— 摇铃 `B` 把它们吓跑。
- **夜骑**：天黑后车头灯自动亮起（真正的 SpotLight 照车与鸟 + 地形着色器里的同参数聚光 + 淡淡的体积光锥），草地上飘着可以收集的**萤火虫**。开局可选「黄昏 / 夜晚 / 昼夜循环」。
- **阵风**：不定时侧风，车头会被轻微推偏、扬起沙尘（设置里可关）。

## 运行

ES Module + importmap 需要 HTTP 协议，直接双击 `index.html` 会因 CORS 失败。

```bash
cd pelican-bike-3d
python3 -m http.server 8931
# 打开 http://127.0.0.1:8931/index.html
```

three.js 已经放在 `vendor/` 里（本地引用），离线也能跑。

## 操作

| 键 | 作用 | 键 | 作用 |
|---|---|---|---|
| `W` / `↑` | 加速（空中：压低车头） | `1`–`4` | 切换机位 |
| `S` / `↓` | 刹车（空中：抬起车头） | `B` | 摇车铃（驱赶海鸥 / 空中加分） |
| `A` `D` / `←` `→` | 转向（空中：转体） | `P` | 拍照（任务判定 + 相册；观光模式另存原图） |
| `Space` | 起跳 | `Esc` | 暂停 / 菜单 / 返回 |
| 拖拽 | 轨道视角 | `M` | 声音开关 |
| 滚轮 / 双指 | 缩放 | `H` | 隐藏界面 |
| `R` | 回出生点（计时赛：上一个检查点） | `G` | 参数面板（观光模式） |

**手机**：左下虚拟摇杆（左右 = 转向，上推 = 踩踏，下拉 = 刹车），右下「跳 / 铃 / 拍 / 刹」。
触屏按键默认在触屏设备上自动显示，设置里可以强制显示或隐藏。

观光模式默认「自动骑行」——按右下角的「自动」按钮可切到手动操控。

## 几个实现上的关键点

- **统一的光照状态**：天空、地形、海面、草、云、鸟共用同一批 uniform，
  每帧只写一次太阳方向，整个世界同步变色。自研着色器输出线性 HDR，
  色调映射与 sRGB 编码统一交给后处理链末端的 `OutputPass`，
  于是自研材质与 `MeshStandardMaterial` 共享同一套曝光。
- **方向性天空**：地平线的颜色随方位变化 —— 朝阳侧暖橙、背光侧冷蓝紫。
  海面反射与地形天光都调用同一个 `skyColor()`，保证三者严格一致。
- **径向指数网格海面**：单张极坐标网格，环半径按指数增长，
  一张网格同时满足近景（十几厘米）与远景（数公里）的精度需求，
  且没有拼接缝。
- **羽毛**：3094 片羽毛 = 1 个 draw call。每帧把「骨骼世界矩阵 × 羽毛局部矩阵」
  算好写进 per-instance 的 mat4 属性。
- **IK**：鹈鹕的翅膀搭在车把、脚掌踩在踏板上，都由世界空间的两骨 IK 解算，
  所以车把怎么转、踏板怎么转，手脚都跟得住。
- **画质档位分两处**：`state.quality` 决定「一次性」的东西（草的数量、地形 LOD、
  阴影贴图尺寸），`effects.bloomBase` 决定「每帧重算」的辉光强度。
  两者必须分开 —— `Effects.render()` 每帧都会用 `bloomBase × 太阳高度系数`
  重写 `bloom.strength`，直接写 `strength` 会在下一帧被覆盖，降档等于没降。
- **转向的符号约定**：`player.steer > 0` 一律表示「车把向右打」（`input.js` 的
  D 键、`bike.js` 的转向组都是这个约定）。但模型是朝 +Z 建的，
  骑手面朝 +Z 时右手边是 **-X**，而 `yaw` 增大是朝 +X 转 ——
  所以「右打把」必须让 `yaw` **递减**（`main.js` 里是 `player.yaw -= …`）。
  写成 `+=` 就会出现「前轮明明朝右、整辆车却往左拐」。
  侧倾同理：`lean > 0` 是绕前进轴把车顶转到 -X（骑手右侧），
  所以右转要配正 `lean`。`autoSteer()` 里「绕圈方向」和「误差修正」两处
  也要跟着取 `radial - π/2` 与 `-diff`，否则鸟会贴着原点原地打转。
- **跳台没有特殊代码路径**：物理每帧问 `game.groundAt(x, z)`，跳台范围内返回跳台表面的高度与法线；
  到了台唇地面突然消失，通用的「刚才还在往上爬、脚下却没了」判定就会把车抛出去 ——
  沙丘顶也会因此偶尔腾空。空中的飞行方向锁定在离地瞬间的 `airYaw`，转体只改车头朝向。
- **游戏层与渲染主循环的接口很窄**：`game.update(dt)` 在物理 → 摆位 → 骨骼之后调用（喙尖位置是这一帧的），
  其余只有 `groundAt` / `handleEvents` / `onTakeoff` / `onLand` / `onPhoto` 几个钩子。观光模式不启用任何玩法模块。
- **不要切换光源的 visible / castShadow**：three 会因为灯的数量变化重编译所有内置材质的着色器。
  太阳落山改为淡出 `shadow.intensity`，车头灯白天只是强度为 0。

几个做法：

- **贴图是增强，不是依赖**。`js/gfx/textures.js` 在构建世界之前并行加载（进度条接在加载界面上），
  20 秒超时；缺哪张，对应的着色器分支就留在程序化实现，不报错。界面插画走 CSS 背景，缺图只是少一张画。
- **细节色是归一化的**：离线把每张图在线性空间里除以自身平均色，着色器用 `调色板 × 贴图 × gain`。
  于是贴图只带来颗粒与纹路，整体色调仍由黄昏调色板决定；远处 mipmap 平均后正好回到调色板本色，
  与天空、雾、昼夜循环的色彩关系完全不变。`gain` 写在 `ART_GAIN` 里，改贴图时要同步。
- **反平铺**：沙与草在「原尺度」和「旋转 37° × 0.43 倍」两套坐标各采一次，用极低频噪声混合；
  岩石用三平面投影，陡坡不会被拉成长条。分支内采样用 `textureGrad`（导数在分支外求）。
- **无缝与法线**：原图要求模型输出 "seamless tileable"，再用半周期错位 + 噪声羽化修掉残余接缝；
  法线由亮度高度场环绕差分得到（B 通道存高度，用于层间的高度混合）。脚本在 `tools/art/`。
- **色彩空间**：细节色 `SRGBColorSpace`，法线 / 白沫 / 粒子是数据贴图 `NoColorSpace`；全部开 mipmap 与各向异性过滤。
- **画质档**：低档不加载法线贴图，地形只采细节色；运行中自适应降到低档时，地形着色器也随之跳过法线采样。
- **性能**：贴图分支替换掉了几组 fbm / ridged 噪声（沙地风纹、草色、岩色、海面细浪、白沫），
  片元着色器的计算量与原来大致持平；每帧没有任何新分配。

## 本地测试小工具

控制台里有 `window.__pelican`，其中 `__pelican.simulate(秒数, { w: true })` 可以不渲染地快进游戏逻辑
（软件渲染只有 1~2fps 时，自动化测试靠它跑完一局）。
